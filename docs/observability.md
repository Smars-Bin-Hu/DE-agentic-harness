# Observability design

First slice of the observability pillar: local, dependency-free structured logging
of everything Claude Code's hooks can see during a session.

## Sink

- `.claude/logs/events.jsonl` — one JSON object per line, append-only, gitignored.
- `.claude/logs/hook-errors.log` — anything the logger itself fails to do with the
  incoming payload. Kept separate so a broken logger never surfaces as a mysterious
  hook failure in the middle of a session.

## Event envelope

```json
{"ts": "2026-09-10T12:00:00.000000+00:00", "event_type": "PreToolUse", "payload": { ... }}
```

- `ts` — UTC ISO-8601, generated by the logger at write time.
- `event_type` — the Claude Code hook name that fired (see below).
- `payload` — whatever JSON Claude Code sends the hook on stdin for that event,
  unmodified. We deliberately don't re-shape or rename its fields here, so this
  doc doesn't drift out of sync with Claude Code's actual hook payloads — read the
  raw lines in `events.jsonl` to see what a given event currently carries.

## Events wired today

Configured in `.claude/settings.json`, all pointing at `.claude/hooks/log-event.sh
<EventName>`:

- `SessionStart` — also still runs `.claude/hooks/example-hook.sh`, the original
  "hooks work" smoke test, side by side with the real logger.
- `PreToolUse` / `PostToolUse` — matcher `*` (every tool).
- `SubagentStop`
- `Stop`

## Correlation

Don't invent a custom trace/session id — use whatever session or transcript
identifier Claude Code already includes in the hook payload as the correlation key
across all lines from one session. Grep `events.jsonl` for that value to reconstruct
a session's timeline.

## Failure behavior

`log-event.sh` always exits `0`. A logging failure must never block or deny a tool
call or end a session — worst case, an event silently fails to log and a note lands
in `hook-errors.log`.

## Future path

The event schema (`ts` / `event_type` / `payload`) is meant to stay stable even if
the sink changes. When the real DE project lands and centralized logging/tracing is
needed, swap the `>> .claude/logs/events.jsonl` append in `log-event.sh` for a real
exporter (OTel, a log shipper, etc.) — nothing else in the harness should need to
change.
